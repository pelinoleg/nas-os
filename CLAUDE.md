# NAS-OS — инструкции проекта для Claude Code

Домашняя NAS-система для Raspberry Pi 5: движок настройки + веб-панель в стиле «десктоп-окружения».
Этот файл переживает переустановку (он в git), поэтому `claude`, запущенный в папке репозитория,
сразу знает архитектуру и правила. Память в `~/.claude/` — локальная и при переустановке пропадает;
источник правды по проекту — ЭТОТ файл + история git.

## Что это и где что лежит
Репозиторий: **github.com/pelinoleg/nas-os** (ветка `main`). `gh` авторизован.
- `nas-web.py` (~5000 строк) — **stdlib-only** HTTP-сервер (ThreadingHTTPServer) от **root**, порт 80.
  Отдаёт статику из `web/`, REST `/api/*`, WebSocket `/ws/term`. Мост к движку:
  `bash nas-wizard.sh api <action>` через env `NASW_*`. Никаких внешних Python-зависимостей.
- `nas-wizard.sh` (~2500 строк) — движок+инсталлятор. Интерактивный (whiptail) и headless
  API-режим (`nas-wizard.sh api <action>`, вызывается из nas-web без whiptail).
- `web/desktop.html` — весь десктоп: инлайн `<style>` + инлайн `<script>` (ванильный JS, без сборки).
- `web/setup.html` — мастер первичной настройки (отдельная страница).
- `web/sw.js` — service worker (network-first; HTML — только из сети).
- `install.sh` — `curl -fsSL .../install.sh | sudo bash` → `git clone/reset --hard origin/main`
  в `/opt/nas-os`, ставит службу `nas-web` оттуда. **Переустановка воспроизводит текущий код 1:1.**
  Запускает `nas-wizard.sh api system` = `stage_system_apply` (авто-база, headless). Что база
  ставит из коробки (2026-07-20 расширена): пакеты (STACK/UTIL/PI + docker + gh), watchdog,
  uas-off, usb-timeout, smartd-guard, thumbs-таймер, **avahi+libnss-mdns** (`.local`),
  **Samba** (`install_smb_shares` — вкладка Sharing живая, шар ноль), **drivetemp** (темп. SATA),
  notify-helper, motd, **netguard** (сетевая устойчивость — теперь в базе, не в стадии backup)
и **unattended-upgrades** (2026-07-20: авто-security-обновления в базе — бокс без присмотра не
копит CVE; канал только security, тумблер в панели остаётся). Целевая ОС — **Debian/RaspiOS**:
install.sh на другой ОС (Ubuntu) громко предупреждает и спрашивает подтверждение через `/dev/tty`
(пайп `curl|bash` — stdin занят скриптом), headless-обход `NASOS_FORCE_OS=1`. Пакеты, которых
установщик не нашёл в репах (переименование в новом Debian), собираются в
`/var/lib/nas-wizard/skipped-packages` (`report_skipped_packages`, громкая сводка в конце
`api system`; «Pi packages» на не-Pi — ожидаемо, не шумим) → `stats().missing_pkgs`
(dpkg-перепроверка, TTL 5 мин) → несмахиваемая плашка `.basepkgs` внизу стола
(`paintBasePkgs`): исчезает САМА, когда пакеты доставлены, кнопки «скрыть» нет намеренно.
  Дальше — диски/пул/шары/стеки/тюнинг в панели/веб-мастере (железо у всех разное).

## Рабочий цикл разработки
1. Правишь файл.
2. **Питон**: `sudo systemctl restart nas-web` (обязательно — код в памяти службы).
   **Статика** (`web/*`): рестарт не нужен, сервер читает с диска; но браузер/кэш — см. ниже.
3. Проверка: `python3 -m py_compile nas-web.py`, `bash -n nas-wizard.sh`, для JS —
   вынуть `<script>` и `node --check`, для CSS — проверить баланс `{` / `}`.
4. **Всегда коммить И пушить** каждую законченную правку (пользователь может уйти/выключить NAS).
   Подпись коммита: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
5. **Документация — часть правки, не после.** Куда писать:
   - **правило, грабля, изменение архитектуры или состава установки** → `CLAUDE.md` (он грузится
     в контекст ВСЕГДА, поэтому туда только то, что нужно всегда);
   - **что именно сделано, как проверено, детали фичи** → `docs/<область>.md` (открывается по
     необходимости). Новая область — новый файл + строка в указателе «Где что записано».
   Файл не должен отставать от кода: это единственный источник правды, переживающий переустановку.
   Правило пользователя (2026-07-22): держать документацию актуальной и всё пушить — по умолчанию,
   без напоминаний. **CLAUDE.md держать компактным** (2026-07-27: он разросся до 337 КБ ≈ 96k
   токенов НА КАЖДОЕ сообщение, что съедало лимит пользователя; после разбора — 60 КБ).
6. Дев-хост = сам NAS (Pi 5). Служба `nas-web` — `enabled` (стартует после ребута сама).

## ЖЕЛЕЗНЫЕ ПРАВИЛА (нарушение = сломанная переустановка / несогласованный UI)

### 1. Полнота установщика (wizard-completeness)
Любое ГЛОБАЛЬНОЕ изменение системы (udev-правило, systemd-юнит, пакет, конфиг в `/etc`,
sudoers, fstab-логика) ОБЯЗАНО быть прописано в `nas-wizard.sh`/`install.sh`, иначе после
переустановки оно исчезнет. Если правишь «живьём» на боксе — параллельно правь генератор
в визарде. Секреты/конфиги пользователя (пароли, `nas-backup.json`, `desktop.json`, задачи)
в репо НЕ входят — они восстанавливаются из «Настройки → Бэкап настроек» (`_bk_sources()`).
**Что кладёт бэкап настроек**: весь `~/nas-config/` (тема/окна/ярлыки/обои, glance.json,
screen.json, storage.json — выбор основного хранилища, профили и история приложения Backup,
кэш иконок), `etc/nas-os/{webauth,nas-backup}.json` (пароль панели, главный NAS), `etc/nas-wizard/`
(motd, usb-import), Samba (`smb.conf` + `passdb.tdb` — пароли SMB-юзеров), `opt/stacks/*/`
(compose+.env стеков), SSH-ключ push-бэкапов (`/root/.ssh/nas-backup`). `reference/` — только
справочно (НЕ авто-восстановление): `fstab`/`snapraid.conf`/`exports` (диски другие — руками) и
`netplan/*.yaml` (Wi-Fi-пароль/статический IP; секретная секция «Сеть»). Секретные секции
(webauth/nasbackup/network) прячутся за отдельным подтверждением при восстановлении. Дефолтный
путь — основное хранилище (пул или выбранный USB через `storage_root()`), без него — системный
`/var/backups/nas-os` (эфемерно, панель предупреждает).

### 2. Дизайн-система (весь новый UI обязан следовать)
Токены — CSS-переменные, тема через `:root[data-theme]` + `@media prefers-color-scheme`.
- НЕ использовать солид-цвета (`#hex`, `var(--bg)`, `var(--surface)`) как заливку карточек/панелей
  ВНУТРИ окон — только стекло `--glass`/`--card`. `var(--bg)` (сплошной) = ТОЛЬКО рабочий стол/body.
- **Elevation в тёмной теме = белый слой с прозрачностью** поверх материала (не осветление того же цвета).
- **Активные табы/сегменты/сайдбары — «белая фишка»**: `background:var(--sel)` + акцентный ТЕКСТ +
  `box-shadow:var(--sh-sm)`. НЕ заливать активное солид-акцентом.
- **Адаптивные поверхности**: `applySettings()` считает фактическую яркость фона каждой поверхности
  (menubar/dock/`.wdg`/`.win`/`.dialog`/`.menu`) и ставит scoped-переменные на `:root`:
  `--{mb|dock|wdg|win}-bg/-bf/-fg/-dim/-line/-accent/-good/-warn/-danger/-track`. Цвета текста/акцента
  подгоняются по контрасту через `accentAdj(hex, effL)` (WCAG). Новый элемент внутри поверхности —
  бери `var(--good/--warn/--danger/--track/--accent)` (они уже контрастно-подогнаны), НЕ хардкодь hex.
- **Профили тем**: все стилевые настройки (`THEMED_KEYS`) РАЗДЕЛЬНЫ для light/dark
  (`SET.themeProfiles`). Новую стилевую настройку — обязательно в `THEMED_KEYS`.
- Иконки — `svg(name,size)` (Lucide-подобные пути в объекте `P`/`I`). Тултипы — `tipHTML()`/`.tip`
  (тёмный пузырь, НЕ на `--ink`). Кнопки `.btn`/`.iconbtn`, сегменты `.seg`, тумблеры `.tgl`,
  диалоги `#scrim`+`.dialog`, поповеры бара `mbPop()` (класс `.mbpop`).
- Прежде чем добавлять окно/компонент — переиспользуй существующие классы/хелперы.

### 3. Язык интерфейса — ТОЛЬКО английский (рантайм-i18n СНЯТ)
UI пишется СРАЗУ по-английски — это единственный язык интерфейса. Словаря `web/i18n.js`
и рантайм-перевода БОЛЬШЕ НЕТ: их выпилили осознанно (ветка `i18n-english-only`, влита в
main — коммит «снос рантайм-i18n — english-only»). Что осталось как заглушки для
совместимости старых call-site'ов, а НЕ как живой слой перевода:
- `nasTr` в `desktop.html`/`setup.html`/`screen.html` — тождественная функция
  (`window.nasTr=function(s){return s}`), `NAS_LANG="en"` захардкожен.
- `tr()` в `nas-web.py` — identity-pass (`return text`), оставлен только чтобы
  серверные call-site'ы (Pushover, лейблы экрана) не падали.
Правила для нового кода: **никаких русских UI-строк** — пиши по-английски. Оборачивать
новую строку в `nasTr(...)` не нужно (заглушка ничего не делает; существующие обёртки не
трогай — они безвредны). Строки `meta.json` в каталоге приложений — тоже английские.
**НЕ возвращай рантайм-словарь/второй язык без явной просьбы пользователя.**

**Комментарии в коде — ПО-АНГЛИЙСКИ.** Старые русские не переводим массово (огромный diff,
шум в `git blame`), но всё новое и всё, что правишь по ходу, комментируй по-английски —
файлы переходят постепенно. Если когда-нибудь понадобится массовый перевод комментариев —
только через токенизаторы (`tokenize`+`ast` для питона; сканер состояния
строка/шаблон/regex для JS и shell), инвариант: код без комментариев обязан остаться байт
в байт прежним (наивный `sed` по `#`/`//` ломает URL, `${VAR#...}` и регулярки).

### 4. Адаптив (десктоп НЕ трогать — всё под media-queries / `isPhone()`)
Флаги: `isPhone()` (≤640), `isTablet()` (641–1024), `isTouch()` (pointer:coarse).
- Планшет+телефон (≤1024): окна **полноэкранные** (`.win{inset:40px 0 …dock 0 !important}`),
  `openWin` пропускает drag/resize; **один док внизу** — зарезервированная полоса с гориз. скроллом
  (контент резервирует его высоту, не прячется под ним); вертикальные сайдбары окон
  (`.set-nav`, `.dm2`) → горизонтальные «таблетки»/лента; тап-таргеты крупнее, инпуты 16px.
- Кнопка «назад» в шапке окна (`.wback`) → `goHome()`. `.wall-refresh` и т.п. скрыты на ≤1024.
- Не полагайся на `!important`-инсет против инлайн-стилей без проверки специфичности (был баг:
  `body.dock-left .desk{bottom:0}` перебивал мобильный отступ по специфичности).

## Кэш / доставка (важно для мобильных)
HTML отдаётся `Cache-Control: no-store` (мобильные при `no-cache` держали старую оболочку).
`web/sw.js` — network-first, навигация только из сети; при правках, если телефон видит старое —
сбросить SW (закрыть вкладку/PWA и открыть заново). При изменении shell-кэша поднимай `CACHE` (v↑).

## Ключевые грабли
- **USB-SATA мосты (UAS)** отдают диск как `ID_BUS=ata`, а не `usb` → udev-правила матчить по
  `ENV{ID_USB_DRIVER}=="?*"` (ловит usb-storage и uas), НЕ по `ID_BUS==usb`.
- **USB-диск уходит ОФЛАЙН посреди бэкапа → ext4 в аварийный read-only.** 2026-07-12 18:46:
  Ugreen (RTL9210) + Seagate ST4000LM024 (2.5" **SMR**): команда записи висела 68 с (SMR-диск
  ушёл во внутреннюю перетасовку), ядро на 30-й секунде (дефолтный таймаут SCSI) объявило
  ошибку → `Device offlined - not ready after error recovery` → `Remounting filesystem read-only`.
  Симптом в панели обманчив: прогон обрывается, а СЛЕДУЮЩИЙ красит ВСЕ папки красным — rsync не
  может даже `readdir` приёмника (`Input/output error (5)`), выглядит как «бэкап всё сломал».
  Диагноз — `dmesg` (`cmd_age=68s`, `offlined`) + `mount` (флаг `emergency_ro`). SMART при этом
  ЧИСТЫЙ (Reallocated/Pending/Uncorrect/CRC = 0, error log пуст) — носитель ни при чём, виноват
  таймаут. Лечение — udev-правило в `install_automount`: `device/timeout` = 180 с для USB-дисков.
  После такого обрыва обязательно `umount` + `e2fsck -fp` (журнал оборван).
- **Таймаута мало: UAS добивает диск сам. UAS ВЫКЛЮЧЕН ВСЕГДА с 2026-07-12** (`install_uas_off()`).
  Через 2 часа после лечения таймаутом — второй обрыв бэкапа, уже НЕ по таймауту (180 с
  применились). В 19:38 по диску пошёл `smartctl` (ATA pass-through, `opcode=0x85` — smartd
  и Scrutiny) ПОКА rsync писал; команда зависла, и `uas_eh_abort_handler` не смог отменить её
  в одиночку → `uas_eh_device_reset_handler` → reset ВСЕГО usb-устройства → оборваны все
  inflight-записи → офлайн → `emergency_ro`. Суть: **error recovery у UAS ресетит устройство
  целиком**, у usb-storage (BOT) зависшая команда падает одна. BOT «медленнее» только на бумаге:
  потолок и так гигабитная сеть (118 МБ/с) и сам HDD (~120 МБ/с).
  Одной глобальной ручки НЕТ: **`uas` вкомпилен в ядро Pi** (`modinfo uas` → `(builtin)`), поэтому
  `blacklist uas` в `modprobe.d` — пустышка; единственный рычаг `usb-storage.quirks`, и он требует
  явный VID:PID, шаблонов не понимает. Старая опция «Отключить UAS» была ловушкой: она собирала
  VID:PID только тех дисков, что воткнуты В МОМЕНТ её запуска, — Ugreen подключили позже, флаг
  горел «включено», а мост все эти месяцы жил на UAS. Поэтому опции больше НЕТ (ни в визарде, ни
  в мастере, ни в панели), а список сам себя поддерживает: udev-хук `nas-uas-off.sh` ловит любой
  мост с `ID_USB_INTERFACES ~ ":080662:"` (= умеет UAS; у флешек-BOT только `:080650:`), дописывает
  его в `/sys/module/usb_storage/parameters/quirks` И в `cmdline.txt`, затем переподнимает
  устройство (`authorized` 0→1) — оно перепривязывается к usb-storage без ребута. Живой параметр
  правится на лету, так что чинить можно и работающий бокс. Любой список «поддерживаемого железа»,
  собранный один раз, протухнет — собирай его по событию.
- **Дочерний процесс nas-web умирает при рестарте службы.** systemd убивает ВСЮ cgroup службы,
  поэтому `sudo systemctl restart nas-web` (наш обычный цикл разработки!) молча уносил sshfs-демоны
  SSH-серверов ФМ, оставляя мёртвые точки монтирования. Симптом обманчив: `mount` показывает маунт,
  а любое обращение — `Transport endpoint is not connected`, ФМ пишет «not a directory».
  Усугубляло то, что `_remote_mounted()` считал маунт живым по факту наличия в `/proc/mounts` →
  панель отвечала «уже смонтировано» и отказывалась перемонтировать. Лечение: **долгоживущий
  процесс — в СВОЙ transient-юнит** (`systemd-run --unit nas-remote-<id> --collect`, `sshfs -f`,
  `Restart=on-failure`, `ExecStopPost=umount -l`) — переживает рестарт панели, а упавший sshfs
  systemd поднимает сам. Живость маунта проверять `statvfs` (на битом FUSE ядро отвечает ENOTCONN
  сразу, без похода на сервер), а НЕ грепом `/proc/mounts`. Пароль — через `--setenv` (окружение
  юнита читает только root), НЕ в argv (`/proc` виден всем); `StandardInputText` транзиентному
  юниту задать нельзя — systemd-run его не принимает.
- **Бэкап: у задачи свой `dest`, и он не следует за общей папкой-приёмником.** Каждая задача хранит
  `dest`, посчитанный в момент добавления источника. Смена «общей папки-приёмника» меняла только
  `dest_base`, а прогон идёт по `dest` задачи → rsync молча лил в СТАРУЮ папку, пока панель
  показывала новую. Лечение: в режиме единой папки `dest` — чистая функция от (`dest_base`, `src`),
  и `nb_save()` выводит его САМ (`_nb_dest_for`, то же правило, что `destFor` в UI), не доверяя
  копии из запроса. Общее правило: если значение выводимо — выводи его на сервере, а не храни
  копию, которая разъедется с источником.
- **Роль по умолчанию в диалоге форматирования = «Данные» → флешка молча уходит в ПУЛ.**
  2026-07-12: пользователь форматировал внешний USB-диск, роль не трогал — диск стал веткой
  mergerfs (`/mnt/disk3`), попал в fstab и в пул. Вынь такой диск — часть `/mnt/storage`
  исчезнет. Лечение: у USB-диска (`tran=="usb"`) роль по умолчанию «Съёмный», а выбор «Данные»
  для съёмного диска показывает, чем это кончится. Разбор завала: строку из `/etc/fstab`,
  `umount`, `rmdir /mnt/diskN`, затем `nas-wizard.sh api mergerfs` — он пересобирает ветки из
  фактически смонтированных `/mnt/disk*` (`mounted_data_disks`), руками юнит не правь.
- **FAT32 на приёмнике бэкапа = гарантированный обрыв.** Потолок файла 4 ГиБ — rsync падает
  с `File too large (27)` и роняет ВСЮ задачу (не «пропускает файл»). Плюс vfat без `iocharset`
  монтируется как **ascii**, и любое имя с кириллицей падает с `mkdir … Invalid argument (22)`.
  Автомонтирование теперь даёт vfat `iocharset=utf8`, а панель предупреждает про 4 ГиБ ДО
  запуска. Приёмник бэкапа — только ext4 (exfat, если диск нужен и на Windows/Mac).
- **Профиль бэкапа в API передаётся ключом `p`**, а не `profile`/`id`. Ошибёшься — запрос уйдёт в
  профиль по умолчанию (последний сохранённый) и перепишет ЕГО настройки. Проверено на себе.
- **`include` в `smb.conf` ставить ТОЛЬКО в самый КОНЕЦ файла (top-level), НЕ после `[global]`.**
  `include` вклеивается текстом буквально: если он стоит внутри `[global]`, а инклуд-файл содержит
  `[global]`+секции шар, то все глобальные параметры smb.conf, идущие ПОСЛЕ строки include,
  припишутся к последней шаре инклуда (`testparm`: «Global parameter … found in service section!»)
  и потеряются из global. Проверено `testparm` 2026-07-20. Поэтому и панельный
  `include = /etc/samba/nas-shares.conf`, и `tm_ensure_include` (Time Machine — там был этот баг,
  исправлен) дописываются В КОНЕЦ, с нормализацией старого кривого размещения (снять любую строку
  include этого файла, дописать в конце). Панель управляет шарами в `nas-shares.conf` (свой
  `[global]` fruit-заголовок + секции), юзерами через `smbpasswd`/`pdbedit`; открытый пароль —
  зеркало в `/etc/nas-os/smb-users.json` (root 0600, секретная секция бэкапа `smbpw`), чтобы
  показывать в UI. Каждая запись → `testparm` → `smbcontrol all reload-config`. Иконка в
  Finder→Сеть = avahi `_device-info` `model=RackMac` (не дублировать с TM-сервисом).
  **Чистый слейт:** дефолтные секции Debian (`[homes]` под `map to guest = bad user` показывается
  на Mac как `nobody`, плюс `[printers]`/`[print$]`) `smb_ensure()` КОММЕНТИРУЕТ (`;`, обратимо,
  идемпотентно), а `[global]` гасит принтеры (`load printers = no`/`printing = bsd`/`disable
  spoolss = yes`/`usershare max shares = 0`). Авто-миграции `[storage]` НЕТ (она «придумывала»
  шару, которую юзер не создавал) — визард тоже больше не пишет `[storage]`; шары/юзеры создаются
  ТОЛЬКО из панели, свежий бокс шарит ноль до первого добавления (`testparm -s` → один `[global]`).
  **ГРАБЛИ гашения дефолтов:** комментировать (`;`) только ОТСТУПЛЕННЫЕ параметры секции; top-level
  директива (`include = …`) или пустая строка ЗАВЕРШАЮТ секцию. Иначе, т.к. наш `include` в конце
  ПОСЛЕ `[print$]` и секции за ним нет, гребёнка «до следующей `[`» закомментировала бы и include —
  smbd не грузит шары, Mac пишет «Connection Failed», `smbclient` → `tree connect failed:
  NT_STATUS_BAD_NETWORK_NAME` (2026-07-20). **Полный доступ к ЛЮБОЙ папке = `force user = root`
  (+ `force group = root`) на КАЖДОЙ шаре** (`_smb_block`). Удаление файла в Unix зависит от прав на
  его ПАПКУ, а не на файл; содержимое расшаренной папки часто чужое (root от USB-импорта, другой юзер,
  даже mode 600) → любой не-root force user упрётся в «you don't have permission». chown (даже
  рекурсивный) — костыль: не масштабируется на произвольные папки и ломается на следующем root-writer'е

  загрузку «с 13:33 вчера» (первые записи новой загрузки идут со стухшим штампом, потом время
  прыгает на +18 ч), а `systemctl status` таймера — «active 18h». Правду говорит `/proc/uptime`.
  Лечение в `avail_track`: `now < beat - 60` → часы неправильные, в журнал не пишем вовсе (60 с —
  допуск на мелкие шаги NTP назад). Правило шире: сравнивать «сейчас» с сохранённой меткой можно
  только убедившись, что «сейчас» ≥ метки — на боксе без RTC время после ребута идёт НЕ вперёд.
- **Правка `nas-wizard.sh` НЕ обновляет установленные им скрипты.** Вчерашний фикс avail-журнала
  пролежал в репо, а `/usr/local/bin/nas-netguard.sh` остался старым — данные продолжали
  портиться «починенным» кодом. После правки генератора — сразу `nas-wizard.sh api <секция>`
  (для сторожа: `api netguard`) на КАЖДОМ боксе, где это уже стоит.

## ⚠️ pi5 МЁРТВ (2026-07-14)
Основной бокс (Pi 5, 3×NVMe + USB-диск) умер ВО ВРЕМЯ БЭКАПА и больше не включается.
Дев-хост и рабочий NAS временно — **pi4** (бокс с тач-экраном, SD-карта, дисков пока нет).
История питания pi5 в граблях: PMIC уже вырубал плату под нагрузкой при слабом БП
(вылечено 27 Вт БП 2026-07-11) — смерть под нагрузкой бэкапа укладывается в тот же паттерн.
При реанимации сначала: снять ВСЁ (NVMe-шляпа, USB-диски), холодный сброс PMIC
(питание вынуть на 5+ мин), проверить БП/кабель на pi4 (у обоих USB-C). Приёмник бэкапа
после обрыва — обязательно `e2fsck -fp` (журнал оборван, см. граблю про emergency_ro).
Данные целы независимо от платы: ветки пула — обычные ext4, mergerfs хранит файлы
целиком по веткам → любой NVMe читается через USB-адаптер на pi4.

## Уведомления: состояние ≠ событие (2026-07-27)
Измерено на боксе: 550 событий за 14 дней (≈39/сутки), из них 84 % — info, а 25 % объёма — ОДИН
факт «есть обновления», записанный 136 раз. Пользователь перестал открывать ленту и выключил
Pushover — и вместе с шумом потерял сигнал. Три правила, по которым это устроено теперь:
- **Состояние — не событие.** `_EVENT_COND` (обновления, «бэкап не ходил», температура, износ,
  недоступный приёмник…) даёт ОДНУ запись, которая живёт, пока состояние истинно: считает повторы
  (`n`), обновляет текст, поднимает уровень, если стало хуже, и НЕ размножается даже после
  прочтения (старый дедуп сливал только непрочитанное за 4 ч — поэтому и выходило 136 записей).
  Настоящие события (загрузка, прогон, подключённый диск) по-прежнему пишутся каждый раз.
- **Телефон — только для того, что не ждёт.** `_PUSH_NOW` — короткий список (read-only ФС, сыплется
  диск, нет запаса питания, перегрев, заблокированное массовое удаление, пропавшая ветка пула…);
  `push_mode` = important (умолчание) | all (как было) | off, настраивается в «Уведомления».
  ПРАВИЛО: канал, который звонит по любому поводу, выключают целиком — и тогда теряют важное.
- **Остальное — вечерняя сводка.** `_events_digest()` строится ИЗ САМОГО ЖУРНАЛА (отдельного
  состояния не нужно): открытые состояния первыми, с «идёт N дней», затем проблемные события,
  затем «столько-то прочего, ничего страшного»; пустой день отвечает «Nothing needs you» —
  молчание тоже ответ. Сводка включена по умолчанию (`summary_enabled`), слот считается через
  `sched_last_due` (рестарт в её минуту больше не съедает сводку).
ВАЖНО для пользователя: сводка уходит в Pushover, поэтому его тумблер надо включить обратно —
теперь он не звонит по пустякам.
- **ГРАБЛЯ, которую создал сам этот режим:** в таблице событий колонка «Push» после введения
  `push_mode` стала ВРАТЬ — тумблер включён у 48 событий, а звонить может 17. Включённый, но
  заглушенный режимом переключатель — это ложь на экране (та же семья, что «редактор даёт править
  файл, который не сохранит»). Лечение: `/api/monitor` отдаёт `push_now` (список неотложных),
  таблица помечает такие строки подписью **rings**, а заглушенные приглушает (`.ev-c.is-gated`)
  и объясняет тултипом «ждёт вечерней сводки». Пояснение под таблицей переписано: «Push» = МОЖЕТ
  дойти до телефона, решает режим сверху. Там же сказано, что вкладка сохраняет себя сама, а
  кнопка «Save keys» — только для двух ключей Pushover (вопрос пользователя: «там save keys —
  только ключи сохраняет?»).
- **Вид ленты переделан (окно «Notifications»)**: плоская река одинаковых строк → карточки по дням
  (`.nt-grp`/`.nt-gh`, язык Kopia-истории), разделители между строками, уровень несёт ЦВЕТНАЯ левая
  грань (crit/warn/ok), время компактное с табличными цифрами, а открытые состояния подняты
  ОТДЕЛЬНЫМ янтарным блоком «Still going on — N» с возрастом («6 h», «3 d») — состояние не новость,
  ему не место в хронологии. **ГРАБЛЯ, которую нашёл только рендер:** список приходит в порядке id,
  а у состояния время (`t2`) двигается вперёд при каждом повторе — на экране получилось 14:31 выше
  09:00 выше 14:08. Сортировать надо по `t2||t`, а не по порядку записи. Правило: новую вёрстку
  списка проверять КАРТИНКОЙ на настоящих данных — по коду это не видно.
- **ГРАБЛЯ (нашлась в тот же день): чистка журнала по ПЕРВОМУ появлению убивала живые состояния.**
  Запись состояния хранит дату НАЧАЛА (из неё делается «идёт N дней»), а `log_event` отбрасывал
  записи по `t < cutoff` — значит долгоживущее состояние удалялось и тут же возвращалось НОВОЙ
  записью, с потерей счётчика и возраста, да ещё и как свежее уведомление. Чистка теперь идёт по
  ПОСЛЕДНЕЙ активности (`max(t, t2)`), проверяет ВЕСЬ список (старый шорткат смотрел только на
  первую запись, считая её самой старой — одно живое состояние в начале замораживало чистку
  целиком) и вызывается В НАЧАЛЕ `log_event`, а не в конце: ветка слияния состояния выходит
  раньше, поэтому чистка в хвосте не выполнялась вообще. 5 ассертов.
- **«System started» больше не врёт при рестарте панели.** Событие писалось на каждый старт
  процесса — а панель рестартуется несколько раз в час, когда над ней работают. Теперь смотрим
  `/proc/uptime`: меньше 5 минут — это загрузка бокса, иначе это просто перезапуск службы и новость
  из этого не делаем.
- **Разовая миграция журнала** `_events_merge_conditions()` (флаг `condv` в файле, идемпотентна,
  вызывается на старте): схлопывает дубли, оставленные старым правилом. На боевом журнале
  550 → 254 записи, суммарные счётчики сохранены, первое появление берётся самое раннее (иначе
  «идёт N дней» врало бы), id и текст — от самой свежей. Отрепетировано на КОПИИ файла до применения.

## Скрытие иконок (2026-07-27)
Скрыть ПО ОДНОЙ иконке можно было и раньше (ПКМ по ярлыку стола → «Hide from the desktop»,
`SET.deskHidden`; по иконке дока → «Remove from Dock», `SET.dockHidden`; вернуть — ПКМ в Launchpad).
Не хватало двух вещей, обе добавлены: (1) **выключить все ярлыки разом** — `SET.deskAppsHidden`,
тумблер «Hide app shortcuts» в Настройки → Оформление → Виджеты, рядом с «Hide the widget panel»;
`renderApps()` выходит сразу, Launchpad не трогается (в подписи и тосте прямо сказано, что
приложения остались там); (2) **длинное нажатие** — `longPress(node, fn)` (500 мс, отмена при
сдвиге >10 px) на ярлыках стола и иконках дока: у настенного тач-экрана и телефона нет правой
кнопки, и меню скрытия было там недостижимо в принципе. ПРАВИЛО: если действие живёт только в
контекстном меню, на таче его НЕТ — либо длинное нажатие, либо дубль в настройках.

**ГРАБЛЯ: меню стола перекрывало меню иконки (2026-07-27).** Пользователь: «нет ПКМ на иконках,
там от рабочего стола показывается» — и был прав, а я до этого уверял, что скрытие ярлыков
работает. Обработчик иконки вызывал `preventDefault()` и `showMenu()`, но НЕ останавливал
всплытие: событие доходило до `.desk`, тот открывал своё меню, и оно затирало только что
показанное (`showMenu` рисует одно меню на всех). Поэтому функция была недостижима, хотя код её
существовал месяцами. Лечение двойное, потому что это два разных вопроса: у иконки —
`e.stopPropagation()` («событие обработано»), у стола — `if(e.target.closest('.app,.wdg'))return`
(«а моё ли оно вообще?»). ПРАВИЛО: контекстное меню на вложенном элементе БЕЗ `stopPropagation`
не работает — оно показывается и тут же заменяется меню родителя; проверять надо кликом, а не
чтением кода (у меню томов это было сделано правильно с самого начала — расхождение внутри одного
файла заметно только на экране).
**Рамка выделения на столе** (`initDeskSelect` + `.selbox`): протяжка мышью по пустому месту рисует
полупрозрачную акцентную рамку, как в Windows/macOS. Осознанно ДЕКОРАТИВНАЯ — ничего не выделяет,
потому что действий над выделенным на столе нет; это обратная связь «поверхность живая». Не
запускается на `.app/.wdg/button/input/.win`, снимается на mouseup, `user-select:none` на время
протяжки. Проверено в живом браузере через CDP: 340×130, фон `--accent` 14 %, рамка 70 %,
после отпускания не остаётся ни одного элемента.
**Ярлыки из docker-меток теперь управляются списком** в Настройки → Оформление → Виджеты
(`lsAppsList`): каждый найденный `web-desktop.*`-ярлык с тумблером, плюс тумблер «Hide app
shortcuts» (`SET.deskAppsHidden`) — выключить все разом. ПРАВИЛО: то, что появляется САМО
(автообнаружение), обязано иметь видимое место управления — прятать это в контекстное меню
значит, что пользователь никогда не узнает о такой возможности.

## Правила, добытые практикой
Каждое — цена уже совершённой ошибки. Подробности в `docs/`.

- для скриптовых правок desktop.html: якорить поиск от УНИКАЛЬНОГО комментария секции приложения, резать до СЛЕДУЮЩЕГО известного определения и ASSERT'ить, что в вырезаемом куске ровно ожидаемое число `function` и нет чужих маркеров (winResil/winRclone…).
- пикер папок в панели ОДИН — `pickFolder`; не плодить свои.
- дизайна детали: важное и крупное сверху (что бэкапим), метрики плитками, история — с легендой и понятной единицей; настройки — свёрнуты.
- любое поле в диалоге, у которого Enter имеет СВОЙ смысл (поиск, навигация, создание), обязано нести `data-noenter` — иначе оно молча делает ДВА действия.
- недоступный вариант лучше показать выключенным с причиной, чем спрятать.
- любой новый `toLocale*` — только с `LOC`.
- баланс иконок — ОПТИЧЕСКИЙ (насколько глиф заполняет свой бокс), не по CSS-размеру; RAW_LOGOS обычно надо подкручивать scale/translate под квадратный бокс.
- тесты, вызывающие мутирующие kp-функции, обязаны восстанавливать состояние (пароль, backups, history ts).
- в СВЕТЛОЙ теме различать поверхности внутри окна заливкой нельзя (всё белое) — только тонировка/рамка/тень.
- не используй «поле = null» как способ инвалидировать кэш, если это же значение служит чужому коду сигналом «инициализируйся» — race неизбежен.
- наличие/отсутствие пинов проверять серверно по ВСЕМУ репозиторию (`kp_snapshots` → `pins`), а не по UI одной папки.
- в шкале, по которой ходят, ни ширина, ни вес шрифта не должны зависеть от выбора.
- вердикт проверки не имеет права быть оптимистичнее собственных наблюдений.
- если пользователь боится нажать кнопку — объяснение должно жить В приложении, а не в голове и не в git.
- аккордеоны хороши для одного скрытого блока; когда их становится два и больше — это уже вкладки.
- «предыдущее значение» для сравнения бери из последнего УСПЕХА, а не из последней записи.
- разные файлы под одним URL нельзя валидировать датой — им кэш противопоказан.
- перед подкруткой масштаба логотипа смотри его `getBBox()` — если арт уже упирается в границы viewBox, любой масштаб >1 это обрезка, а не увеличение.
- меняя набор значений у модульной переменной-состояния, добавляй нормализацию — старое значение переживает перезагрузку страницы (и живёт в чужих вкладках).
- на боксе без RTC проверять не `who -b`/`--list-boots`, а `/proc/uptime` — они расходятся ровно на величину скачка.
- если инструмент умеет делать тяжёлую работу «когда придётся», а мы делаем её по расписанию — автоматику надо гасить, иначе она однажды случится внутри чужой короткой операции.
- подготовительный шаг не имеет права стоить главного, если его результат уже есть в системе.
- если у режима есть сторож, исполняющий его автоматически, то ручное действие, обратное режиму, обязано либо снять режим, либо быть отклонено с объяснением — молча проигрывать сторожу кнопка не имеет права.
- у периодической задачи порог тревоги обязан быть соизмерим с её ПЕРИОДОМ, а не выбран «на глаз»; для ежедневной задачи неделя тишины — это не порог, это отсутствие контроля.
- для любого расписания в этом проекте: слот — это ИНТЕРВАЛ «должен был к моменту X», а не минута-совпадение; и он обязан лежать на диске.
- то, что читается на уровне модуля, не имеет права бросать — иначе бокс теряет веб-интерфейс из-за одной строки в файле состояния.
- прежде чем оптимизировать РАЗМЕР ИСХОДНИКА, посмотри, что реально уходит в сеть — заголовок ответа отвечает на этот вопрос за секунду.
- вопрос «можно ли это сохранить» задаётся при ОТКРЫТИИ, а не после того, как человек напечатал текст; отказ, о котором сообщает исчезающий тост, эквивалентен молчанию.
- любой кэш/валидатор, ключуемый по времени файла, обязан быть наносекундным — секунда это вечность для генератора правок.

Идеи в бэклоге (для Explorer): общие: Telegram-бот, «топ самых больших файлов» в анализаторе,
glance: спарклайны в плитках, пользовательские проверки из `~/nas-config/scripts`;
бэкап наружу — пользователь делает сторонним сервисом в Docker (zerobyte).

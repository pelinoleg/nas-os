# NAS-OS — инструкции проекта для Claude Code

Домашняя NAS-система для x86-бокса на Debian: движок настройки + веб-панель в стиле «десктоп-окружения».
Этот файл переживает переустановку (он в git), поэтому `claude`, запущенный в папке репозитория,
сразу знает архитектуру и правила. Память в `~/.claude/` — локальная и при переустановке пропадает;
источник правды по проекту — ЭТОТ файл + история git.

## Что это и где что лежит
Репозиторий: **github.com/pelinoleg/nas-os** (ветка `main`). `gh` авторизован.
- `nas-web.py` (~5000 строк) — **stdlib-only** HTTP-сервер (ThreadingHTTPServer) от **root**, порт 80.
  Отдаёт статику из `web/`, REST `/api/*`, WebSocket `/ws/term`. Мост к движку:
  `bash nas-wizard.sh api <action>` через env `NASW_*`. Никаких внешних Python-зависимостей.
- `nas-wizard.sh` (~2500 строк) — движок+инсталлятор. Интерактивный (whiptail) и headless
  API-режим (`nas-wizard.sh api <action>`, вызывается из nas-web без whiptail).
- `web/desktop.html` — весь десктоп: инлайн `<style>` + инлайн `<script>` (ванильный JS, без сборки).
- `web/setup.html` — мастер первичной настройки (отдельная страница).
- `web/sw.js` — service worker (network-first; HTML — только из сети).
- `install.sh` — `curl -fsSL .../install.sh | sudo bash` → `git clone/reset --hard` в
  `/opt/nas-os`, ставит службу `nas-web` оттуда. **Переустановка воспроизводит текущий код 1:1.**
  По умолчанию ставится `main`; `NASOS_REF=v2026.08.04` (тег или ветка) пинит установку на
  проверенную версию — боевой бокс ставить С ТЕГА, `main` может быть правкой пятиминутной
  давности. Теги — датные (`vГГГГ.ММ.ДД`), вешать на проверенное состояние.
  Запускает `nas-wizard.sh api system` = `stage_system_apply` (авто-база, headless). Что база
  ставит из коробки (2026-07-20 расширена): пакеты (STACK/UTIL + docker + gh), watchdog,
  uas-off, usb-timeout, smartd-guard, thumbs-таймер, **avahi+libnss-mdns** (`.local`),
  **Samba** (`install_smb_shares` — вкладка Sharing живая, шар ноль), **drivetemp** (темп. SATA),
  notify-helper, motd, **netguard** (сетевая устойчивость — теперь в базе, не в стадии backup)
и **unattended-upgrades** (2026-07-20: авто-security-обновления в базе — бокс без присмотра не
копит CVE; канал только security, тумблер в панели остаётся). Целевая ОС — **Debian на x86**:
install.sh на другой ОС (Ubuntu) громко предупреждает и спрашивает подтверждение через `/dev/tty`
(пайп `curl|bash` — stdin занят скриптом), headless-обход `NASOS_FORCE_OS=1`. Пакеты, которых
установщик не нашёл в репах (переименование в новом Debian), собираются в
`/var/lib/nas-wizard/skipped-packages` (`report_skipped_packages`, громкая сводка в конце
`api system`) → `stats().missing_pkgs`
(dpkg-перепроверка, TTL 5 мин) → несмахиваемая плашка `.basepkgs` внизу стола
(`paintBasePkgs`): исчезает САМА, когда пакеты доставлены, кнопки «скрыть» нет намеренно.
  Дальше — диски/пул/шары/стеки/тюнинг в панели/веб-мастере (железо у всех разное).

## Рабочий цикл разработки
1. Правишь файл.
2. **Питон**: `sudo systemctl restart nas-web` (обязательно — код в памяти службы).
   **Статика** (`web/*`): рестарт не нужен, сервер читает с диска; но браузер/кэш — см. ниже.
3. Проверка: `./check.sh` (всё разом; группы — py/test/sh/gen/js/css/i18n/git).
   **CI**: GitHub Actions гоняет те же проверки на каждый push (`.github/workflows/ci.yml`) —
   красный крест у коммита = «этот коммит не ставить», работает и когда все боксы мертвы.
   ГРАБЛЯ: `.gitignore` тут — белый список (`/*` + разрешения); новый top-level файл/папка
   НЕ попадёт в `git add -A`, пока не добавлен `!/имя` — workflow так молча не доехал до
   GitHub при зелёном пуше. Проверяй появление РАНА, а не успех пуша.
4. **Всегда коммить И пушить** каждую законченную правку (пользователь может уйти/выключить NAS).
   Подпись коммита: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
5. **Документация — часть правки, не после.** Куда писать:
   - **правило, грабля, изменение архитектуры или состава установки** → `CLAUDE.md` (он грузится
     в контекст ВСЕГДА, поэтому туда только то, что нужно всегда);
   - **что именно сделано, как проверено, детали фичи** → `docs/<область>.md` (открывается по
     необходимости). Новая область — новый файл + строка в указателе «Где что записано».
   Файл не должен отставать от кода: это единственный источник правды, переживающий переустановку.
   Правило пользователя (2026-07-22): держать документацию актуальной и всё пушить — по умолчанию,
   без напоминаний. **CLAUDE.md держать компактным** (2026-07-27: он разросся до 337 КБ ≈ 96k
   токенов НА КАЖДОЕ сообщение, что съедало лимит пользователя; после разбора — 60 КБ).
6. Дев-хост = сам NAS (`mininas`, AZW ME mini, Debian 13). Служба `nas-web` — `enabled`.

## ЖЕЛЕЗНЫЕ ПРАВИЛА (нарушение = сломанная переустановка / несогласованный UI)

### 1. Полнота установщика (wizard-completeness)
Любое ГЛОБАЛЬНОЕ изменение системы (udev-правило, systemd-юнит, пакет, конфиг в `/etc`,
sudoers, fstab-логика) ОБЯЗАНО быть прописано в `nas-wizard.sh`/`install.sh`, иначе после
переустановки оно исчезнет. Если правишь «живьём» на боксе — параллельно правь генератор
в визарде. Секреты/конфиги пользователя (пароли, `nas-backup.json`, `desktop.json`, задачи)
в репо НЕ входят — они восстанавливаются из «Настройки → Бэкап настроек» (`_bk_sources()`).
**Что кладёт бэкап настроек**: весь `/var/lib/nas-os/` (тема/окна/ярлыки/обои, glance.json,
screen.json, storage.json — выбор основного хранилища, профили и история приложения Backup,
кэш иконок), `etc/nas-os/{webauth,nas-backup}.json` (пароль панели, главный NAS), `etc/nas-wizard/`
(motd, usb-import), Samba (`smb.conf` + `passdb.tdb` — пароли SMB-юзеров), `opt/stacks/*/`
(compose+.env стеков), SSH-ключ push-бэкапов (`/root/.ssh/nas-backup`). `reference/` — только
справочно (НЕ авто-восстановление): `fstab`/`snapraid.conf`/`exports` (диски другие — руками) и
`netplan/*.yaml` (Wi-Fi-пароль/статический IP; секретная секция «Сеть»). Секретные секции
(webauth/nasbackup/network) прячутся за отдельным подтверждением при восстановлении. Дефолтный
путь — основное хранилище (пул или выбранный USB через `storage_root()`), без него — системный
`/var/backups/nas-os` (эфемерно, панель предупреждает).

**Движки приложений — в автобазе, не по кнопке (2026-08-15).** `rclone` (облако), `kopia`
(снапшоты), `syncthing` (синк устройств) ставятся стадией `system` обоих визардов — веб и TUI.
kopia раньше был «по требованию», хотя тянется ровно как rclone, бинарём с сайта вендора:
движок бэкапа, которого нет в день, когда он понадобился, — единственный отказ, которого у NAS
быть не должно. Кнопка «Install kopia» осталась ретраем на случай провала загрузки. Экран
стадии обязан ПЕРЕЧИСЛЯТЬ то, что ставит (rclone и syncthing стояли месяцами, не названные
нигде, — отсюда «главные приложения не установились»). И стадия обязана возвращать код: панель
красит «готово» по exit 0 и ничему больше, поэтому провалы копятся в `NASW_BASE_FAIL`
(`base_fail`), а `report_base_failures` их называет и возвращает 1. Тест:
`tests/test_wizard_base_install.py`.

### 2. Дизайн-система (весь новый UI обязан следовать)
Токены — CSS-переменные, тема через `:root[data-theme]` + `@media prefers-color-scheme`.
- НЕ использовать солид-цвета (`#hex`, `var(--bg)`, `var(--surface)`) как заливку карточек/панелей
  ВНУТРИ окон — только стекло `--glass`/`--card`. `var(--bg)` (сплошной) = ТОЛЬКО рабочий стол/body.
- **Elevation в тёмной теме = белый слой с прозрачностью** поверх материала (не осветление того же цвета).
- **Активные табы/сегменты/сайдбары — «белая фишка»**: `background:var(--sel)` + акцентный ТЕКСТ +
  `box-shadow:var(--sh-sm)`. НЕ заливать активное солид-акцентом.
- **Адаптивные поверхности**: `applySettings()` считает фактическую яркость фона каждой поверхности
  (menubar/dock/`.wdg`/`.win`/`.dialog`/`.menu`) и ставит scoped-переменные на `:root`:
  `--{mb|dock|wdg|win}-bg/-bf/-fg/-dim/-line/-accent/-good/-warn/-danger/-track`. Цвета текста/акцента
  подгоняются по контрасту через `accentAdj(hex, effL)` (WCAG). Новый элемент внутри поверхности —
  бери `var(--good/--warn/--danger/--track/--accent)` (они уже контрастно-подогнаны), НЕ хардкодь hex.
- **Профили тем**: все стилевые настройки (`THEMED_KEYS`) РАЗДЕЛЬНЫ для light/dark
  (`SET.themeProfiles`). Новую стилевую настройку — обязательно в `THEMED_KEYS`.
- Иконки — `svg(name,size)` (Lucide-подобные пути в объекте `P`/`I`). Тултипы — `tipHTML()`/`.tip`
  (тёмный пузырь, НЕ на `--ink`). Кнопки `.btn`/`.iconbtn`, сегменты `.seg`, тумблеры `.tgl`,
  диалоги `#scrim`+`.dialog`, поповеры бара `mbPop()` (класс `.mbpop`).
- Прежде чем добавлять окно/компонент — переиспользуй существующие классы/хелперы.

### 3. Язык интерфейса — ТОЛЬКО английский (рантайм-i18n СНЯТ)
UI пишется СРАЗУ по-английски — это единственный язык интерфейса. Словаря `web/i18n.js`
и рантайм-перевода БОЛЬШЕ НЕТ: их выпилили осознанно (ветка `i18n-english-only`, влита в
main — коммит «снос рантайм-i18n — english-only»). Что осталось как заглушки для
совместимости старых call-site'ов, а НЕ как живой слой перевода:
- `nasTr` в `desktop.html`/`setup.html`/`screen.html` — тождественная функция
  (`window.nasTr=function(s){return s}`), `NAS_LANG="en"` захардкожен.
- `tr()` в `nas-web.py` — identity-pass (`return text`), оставлен только чтобы
  серверные call-site'ы (Pushover, лейблы экрана) не падали.
Правила для нового кода: **никаких русских UI-строк** — пиши по-английски. Оборачивать
новую строку в `nasTr(...)` не нужно (заглушка ничего не делает; существующие обёртки не
трогай — они безвредны). Строки `meta.json` в каталоге приложений — тоже английские.
**НЕ возвращай рантайм-словарь/второй язык без явной просьбы пользователя.**

**Комментарии в коде — ПО-АНГЛИЙСКИ.** Старые русские не переводим массово (огромный diff,
шум в `git blame`), но всё новое и всё, что правишь по ходу, комментируй по-английски —
файлы переходят постепенно. Если когда-нибудь понадобится массовый перевод комментариев —
только через токенизаторы (`tokenize`+`ast` для питона; сканер состояния
строка/шаблон/regex для JS и shell), инвариант: код без комментариев обязан остаться байт
в байт прежним (наивный `sed` по `#`/`//` ломает URL, `${VAR#...}` и регулярки).

### 4. Адаптив (десктоп НЕ трогать — всё под media-queries / `isPhone()`)
Флаги: `isPhone()` (≤640), `isTablet()` (641–1024), `isTouch()` (pointer:coarse).
- Планшет+телефон (≤1024): окна **полноэкранные** (`.win{inset:40px 0 …dock 0 !important}`),
  `openWin` пропускает drag/resize; **один док внизу** — зарезервированная полоса с гориз. скроллом
  (контент резервирует его высоту, не прячется под ним); вертикальные сайдбары окон
  (`.set-nav`, `.dm2`) → горизонтальные «таблетки»/лента; тап-таргеты крупнее, инпуты 16px.
- Кнопка «назад» в шапке окна (`.wback`) → `goHome()`. `.wall-refresh` и т.п. скрыты на ≤1024.
- Не полагайся на `!important`-инсет против инлайн-стилей без проверки специфичности (был баг:
  `body.dock-left .desk{bottom:0}` перебивал мобильный отступ по специфичности).

### 5. Железо — только x86, и ни одной ручки, которой здесь нет (2026-08-13)
Поддержка **Raspberry Pi выпилена целиком**: система ставится только на x86-бокс
(`mininas`, AZW ME mini, Debian 13) и на ARM больше не поедет. Ушли `is_pi()`/`IS_PI`,
`vcgencmd`, `config.txt`/`cmdline.txt`, EEPROM, throttle-флаги, PSU по device-tree,
Pi-пакеты, `fake-hwclock`, малина в иконках. Прежнее правило «ветвить по факту железа»
отменено вместе с самой развилкой — ветвить больше не между чем.
- **Тумблер, который показан, но не может сработать, ХУЖЕ отсутствующего — он врёт.**
  Правило пережило выпиливание и остаётся главным: вкладка «Hardware» показывает
  ТОЛЬКО настоящие ручки (governor, watchdog), а memory cgroup — это ЧТЕНИЕ
  состояния ядра, не переключатель.
- **Не измерено ≠ всё хорошо, и не измерено ≠ плохо.** Обе стороны стоили ошибок:
  плашка «Power and frequency are normal» из непрочитанного датчика и «Uptime 37 % / 30d»
  на боксе, которому полдня от роду. Нет данных — нет вердикта, плитки просто нет.
- **Температуру CPU брать по ИМЕНИ hwmon** (`_cpu_temp_path()`, `coretemp`/`k10temp`/…),
  `thermal_zone0` — только фолбэк: на x86 это чаще корпус, а не процессор.
- **Имена governor'ов не универсальны** (intel_pstate = только powersave/performance) —
  выбирать из `scaling_available_governors`, не хардкодить `ondemand`.
- **Состояние ядра спрашивать у ядра**: memory-cgroup — по `/sys/fs/cgroup/cgroup.controllers`.
- Марка одна (`web/icon.svg` + PNG), генерируется `tools/make-icons.py` из одного описания
  формы — правь ФОРМУ там, иначе SVG и иконки разъедутся. Отдаётся по `/icon-brand.svg`.
История переезда — `docs/hardware-portability.md`.


### 6. Пакет не встал — говори ЧТО СЛОМАЛОСЬ, и не в одном месте (2026-08-04)
Новый пакет в `STACK_/UTIL_PACKAGES`, без которого отваливается функция ядра NAS, ОБЯЗАН
попасть в `REQUIRED_PKGS` строкой `"пакет|что перестанет работать"` — иначе его пропажа
(переименование в новом Debian) будет тихой. `/var/lib/nas-wizard/skipped-packages` — TSV
`level<TAB>pkg<TAB>stage<TAB>why`, уровни `req|opt`; старый формат `stage: pkg` парсится
как `opt` (`_parse_skipped_line`). Видно в ЧЕТЫРЁХ местах: сводка в конце установки,
SSH-приветствие, плашка на столе, Настройки → Система; плюс кнопка «Install them now»
(`POST /api/pkgs/install`). Ни одна поверхность не смахивается — все перечитывают dpkg.
**ГРАБЛЯ:** блок в motd сначала попал ПОСЛЕ гейта `MOTD_INFO`, а у пользователя `MOTD_INFO=0` —
единственный новый канал был бы выключен чужой настройкой. ПРАВИЛО: добавляя сообщение в
существующий вывод, проверь, не стоит ли оно за чужим выключателем.

## Кэш / доставка (важно для мобильных)
HTML отдаётся `Cache-Control: no-store` (мобильные при `no-cache` держали старую оболочку).
`web/sw.js` — network-first, навигация только из сети; при правках, если телефон видит старое —
сбросить SW (закрыть вкладку/PWA и открыть заново). При изменении shell-кэша поднимай `CACHE` (v↑).

## Ключевые грабли
- **USB-SATA мосты (UAS)** отдают диск как `ID_BUS=ata`, а не `usb` → udev-правила матчить по
  `ENV{ID_USB_DRIVER}=="?*"` (ловит usb-storage и uas), НЕ по `ID_BUS==usb`.
- **USB-диск уходит ОФЛАЙН посреди бэкапа → ext4 в emergency read-only.** SMR-диск завис на записи 68 с,
  ядро на 30-й секунде (дефолт SCSI) объявило ошибку → офлайн → ro. Симптом обманчив: СЛЕДУЮЩИЙ прогон красит
  ВСЕ папки красным (rsync не может даже readdir), а SMART чистый. Диагноз: `dmesg` (`cmd_age`, offlined) +
  `mount` (emergency_ro). Лечение: udev `device/timeout=180` (install_automount); после обрыва `umount`+`e2fsck -fp`.
  Полная история: `docs/incidents.md`.
- **UAS выключен ВСЕГДА** (`install_uas_off()`): его error recovery ресетит ВСЁ usb-устройство — один зависший
  smartctl-запрос (ATA pass-through во время rsync) обрывает все inflight-записи; у usb-storage (BOT) падает одна
  команда, а потолок всё равно сеть и HDD. На Pi `uas` ВКОМПИЛЕН (blacklist — пустышка), рычаг один —
  `usb-storage.quirks` по VID:PID, поэтому udev-хук `nas-uas-off.sh` ловит любой мост по `ID_USB_INTERFACES ~ ":080662:"`
  и дописывает quirk САМ (статический список протухает — с этого всё и началось); на x86 uas — модуль:
  дополнительно blacklist + пересборка initramfs.
  Полная история: `docs/incidents.md`.
- **`systemctl restart nas-web` убивает всю cgroup службы** — sshfs-демоны ФМ умирали; маунт «есть» в /proc/mounts,
  а обращение — ENOTCONN. Долгоживущий процесс — в СВОЙ transient-юнит (`systemd-run --collect`, `Restart=on-failure`,
  `ExecStopPost=umount -l`); живость маунта проверять `statvfs`, не грепом /proc/mounts; пароль — через `--setenv`, не argv.
  Полная история: `docs/incidents.md`.
- **Бэкап: у задачи свой `dest`, и он не следует за общей папкой-приёмником.** Каждая задача хранит
  `dest`, посчитанный в момент добавления источника. Смена «общей папки-приёмника» меняла только
  `dest_base`, а прогон идёт по `dest` задачи → rsync молча лил в СТАРУЮ папку, пока панель
  показывала новую. Лечение: в режиме единой папки `dest` — чистая функция от (`dest_base`, `src`),
  и `nb_save()` выводит его САМ (`_nb_dest_for`, то же правило, что `destFor` в UI), не доверяя
  копии из запроса. Общее правило: если значение выводимо — выводи его на сервере, а не храни
  копию, которая разъедется с источником.
- **Пул разбрасывающий: `category.create=mfs,moveonenospc=mfs`, обратно на `epmfs` не менять.**
  2026-08-14 владелец выбрал `epmfs` (path-preserving), 2026-08-27 — отменил, по факту, а не по
  вкусу. Зеркало Ugreen кладёт в пул папку `Mirror/Ugreen/home` на 1.77 ТБ, а самая большая
  ветка — 916 ГиБ. При path-preserving кандидат на новый файл ровно один — та ветка, где папка
  уже лежит; она ушла ниже `minfreespace=20G` → **каждый** create отдавал `ENOSPC`, хотя в пуле
  было свободно 1.3 ТБ. Прогон умер на 33 % с 16310 ошибками и ещё два часа «шёл», не записав
  ничего. Такая папка при `epmfs` не докопируется никогда — это не настройка порога.
  Цена, принятая осознанно: чётности нет, поэтому смерть ветки уносит её файлы при любой
  политике, но под `mfs` файлы одной папки размазаны → дыра в КАЖДОЙ папке вместо потери
  папок целиком. Терпимо ИМЕННО ЗДЕСЬ, потому что пул на ~99 % — зеркало чужого NAS (765 ГиБ
  Mirror против считанных мегабайт всего остального на момент смены), то есть ровно те данные,
  которые перекачиваются. **Появятся на пуле данные в одном экземпляре — решение пересматривать,
  и настоящий ответ тогда чётность, а не политика.**
  `moveonenospc=mfs` разрешён именно потому, что инвариант снят: политика выбирает ветку в
  момент создания файла, а ветка может перейти порог, пока файл ещё пишется. Под `epmfs` эта
  опция была запрещена (клонировала папку на вторую ветку под нагрузкой) — защищать больше нечего.
  Обязателен `statfs=full`: без него `statvfs()` внутри папки отдаёт СУММУ веток, и шесть
  проверок места в панели обещают терабайты туда, где их нет. Под `mfs` папка со временем
  расползается по веткам и числа сходятся, но НОВАЯ папка по-прежнему живёт на одной ветке —
  а спрашивают о месте как раз тогда. `ignorepponrename` по-прежнему НЕ ставить.
  **`st_dev` внутри пула не различает ветки** — у всех веток он общий (FUSE). Вопрос «тот же
  диск?» решает только `_pool_branch()` (xattr `user.mergerfs.basepath`); три проверки в
  `nas-web.py` жили на `st_dev` и всегда отвечали «да».
- **Роль по умолчанию в диалоге форматирования = «Данные» → флешка молча уходит в ПУЛ.**
  2026-07-12: пользователь форматировал внешний USB-диск, роль не трогал — диск стал веткой
  mergerfs (`/mnt/disk3`), попал в fstab и в пул. Вынь такой диск — часть `/mnt/storage`
  исчезнет. Лечение: у USB-диска (`tran=="usb"`) роль по умолчанию «Съёмный», а выбор «Данные»
  для съёмного диска показывает, чем это кончится. Разбор завала: строку из `/etc/fstab`,
  `umount`, `rmdir /mnt/diskN`, затем `nas-wizard.sh api mergerfs` — он пересобирает ветки из
  фактически смонтированных `/mnt/disk*` (`mounted_data_disks`), руками юнит не правь.
- **FAT32 на приёмнике бэкапа = гарантированный обрыв.** Потолок файла 4 ГиБ — rsync падает
  с `File too large (27)` и роняет ВСЮ задачу (не «пропускает файл»). Плюс vfat без `iocharset`
  монтируется как **ascii**, и любое имя с кириллицей падает с `mkdir … Invalid argument (22)`.
  Автомонтирование теперь даёт vfat `iocharset=utf8`, а панель предупреждает про 4 ГиБ ДО
  запуска. Приёмник бэкапа — только ext4 (exfat, если диск нужен и на Windows/Mac).
- **Профиль бэкапа в API передаётся ключом `p`**, а не `profile`/`id`. Ошибёшься — запрос уйдёт в
  профиль по умолчанию (последний сохранённый) и перепишет ЕГО настройки. Проверено на себе.
- **Samba:** `include` — ТОЛЬКО в самом КОНЦЕ smb.conf: внутри `[global]` глобальные параметры после него приписываются
  к последней шаре инклуда и теряются. Дефолтные секции Debian `smb_ensure()` КОММЕНТИРУЕТ — но только ОТСТУПЛЕННЫЕ
  строки: top-level `include`/пустая строка ЗАВЕРШАЮТ секцию, слепая гребёнка «до следующей `[`» однажды закомментировала
  сам include («Connection Failed»). **Полный доступ = `force user = root` (+group) на КАЖДОЙ шаре**: удаление зависит
  от прав на ПАПКУ, содержимое часто чужое/root — любой не-root force user упрётся в «no permission». Панель владеет
  `nas-shares.conf`; каждая запись → `testparm` → `smbcontrol all reload-config`. Авто-миграции `[storage]` НЕТ.
  Полная история: `docs/incidents.md`.
- `getComputedStyle().getPropertyValue('--x')` НЕ резолвит `var()` внутри кастом-проперти —
  читай уже-вычисленные `--{surface}-good/…` с `:root` (они хексы, поставлены `setProperty`).
- **`.nt-root` переопределяет `--code-fg`** (светлая тема заметок = тёмные чернила) — встроенный CodeMirror получал
  тёмное-на-тёмном. Вешать `ed-dark` на контейнер редактора БЕЗУСЛОВНО; внутри `.nt-root` глобальные токены могут
  значить НЕ то — проверяй фактический computed-цвет.
  Полная история: `docs/incidents.md`.
- **HTML-заметки: подсветка = мод `htmlmixed`, а НЕ `xml`.** Голый `xml`(+`htmlMode`) красит теги,
  но содержимое `<style>`/`<script>` идёт простым текстом. `htmlmixed` (вендрен `web/cm-htmlmixed.js`,
  CM 5.65.16, MIT) делегирует `<style>`→css, `<script>`→js; грузится в `ensureCM` ПОСЛЕ
  cm-xml/css/javascript (зависит от них). `defineMIME("text/html","htmlmixed")` в нём НАМЕРЕННО
  убран — иначе перебил бы `text/html`→xml, на который завязан ФМ; мод берётся по имени `"htmlmixed"`.
- `.menu button{width:100%}` растягивает любую кнопку в поповере — для компактных нужен оверрайд.
- Уведомления фоновых агентов могут врать — сверяй файлы на диске.
- **Слабый БП = PMIC вырубает плату под нагрузкой**: журнал обрывается без shutdown, холодный старт (`rsts 0`),
  watchdog бессилен. Диагноз: `/proc/device-tree/chosen/power/max_current` — нужно 5000 (27 Вт БП); слабый кабель
  тоже роняет переговоры PD до 3000. В панели это строка «Питание» (`psu_ma`); софт-страховка — `web_selfheal()`.
  Полная история: `docs/incidents.md`.
- **comitup УДАЛЁН СОВСЕМ (2026-07-20)**: он поднимал хотспот вместо возврата в домашнюю сеть (NAS жив, но недоступен)
  и дрался с netguard за wlan0. Wi-Fi-резерв делает netguard (профиль в NM); `disable_comitup()`+`wifi_rescue()`
  оставлены обезвреживать comitup из чужого образа.
  Полная история: `docs/incidents.md`.
- **Ежечасный спидтест = ложный обрыв провода.** MySpeed по умолчанию `cron: "0 * * * *"` — ровно в
  :00 он выбирал весь канал (~300/200 Мбит/с, 20–30 с), роутер под нагрузкой ронял ICMP/ARP, и
  netguard объявлял провод мёртвым. Отсюда правило в `eth_healthy()`: жёсткий обрыв (нет carrier /
  адреса / маршрута) — failover сразу, а МОЛЧАНИЕ ШЛЮЗА — только после `GWMISS_MAX`=3 промахов
  подряд. Любую новую проверку «жив ли линк» делать так же: под нагрузкой сеть врёт.
- **«Падает NAS» может оказаться промежуточным роутером.** Спидтест забивал CPU скрытого хопа (GL.iNet с proxy-ARP:
  ВСЕ адреса дома резолвились в один MAC) — форвардинг вставал на 18 с, NAS был чист. Скрытый хоп ищется за минуту:
  `ping -t 1/2/3` + `ip neigh | grep <mac>`. Защита GWMISS_MAX сработала — провод удержан.
  Полная история: `docs/incidents.md`.
- **eth0 + wlan0 в одной подсети = катастрофа.** NM снимает on-link маршрут подсети по ложному
  ACD-конфликту → ответы соседям уходят через шлюз → путь асимметричный → роутер впрыскивает RST.
  Симптом обманчив: `ping` идёт, IPv6/SSH живы, а HTTP висит на «loading…». Лечит `nas-netguard.sh`
  («один активный линк за раз», eth0 главный). Не «чинить маршрут» — держать один интерфейс.
- **`nmcli device disconnect` НЕ держит Wi-Fi выключенным** — autoconnect поднимает его снова, каждый всплеск =
  секунды второго адреса в той же подсети = обманчивые обрывы HTTP. Лечение — `wifi_autoconnect no|yes` в netguard:
  провод жив → autoconnect off; отвалился → yes и поднять (таймер + NM-хук на carrier-down).
  Полная история: `docs/incidents.md`.
- **`${VAR:-{a}-{b}}` в bash ломается**: первая `}` закрывает подстановку, хвост клеится текстом.
  Дефолты с фигурными скобками выносить отдельной строкой. Проверять `${VAR+set}`, а не `:-`,
  если пустое значение — осознанный режим (напр. «без подпапки»).
- `printf '%-12s'` меряет БАЙТЫ: кириллица разъезжает по колонкам. Вывод в терминал — латиницей.
- В `pam_motd`/udev-хуках нельзя `smartctl`/`hdparm` (будят спящие диски) и синхронный `nmcli`
  из NM-dispatcher (дедлок: NM ждёт скрипт, скрипт ждёт NM → `systemctl start --no-block`).
- **Частый опрос × дорогой источник = бокс в полке**: экран раз в 1.5 с честно пересчитывал ВСЕ плитки, включая
  `apt-get -s upgrade` → load 14 и ПУСТОЙ экран (выглядело как баг вёрстки). У каждого источника свой TTL
  (`SCREEN_TILE_TTL`). Ускоряя опрос, сначала посчитай цену КАЖДОГО поля × частоту.
  Полная история: `docs/incidents.md`.
- **Указателей больше, чем кажется**: курсор киоску рисуют мышь донгла, его же Consumer Control (БЕЗ метки
  ID_INPUT_MOUSE) и даже джеки HDMI; `cursor:none`/пустая тема не помогают. Правило перевёрнуто: libinput игнорирует
  ВСЁ, кроме тачскрина. Проверять по открытым дескрипторам `/proc/$(pgrep -x cage)/fd`.
  Полная история: `docs/incidents.md`.
- **`_run()` возвращает СЛОВАРЬ `{ok,code,log}`, а не строку.** `.strip()` у него → AttributeError →
  ручка отвечает 500 → `api()` в панели бросает → вкладка настроек рисует только заголовок.
  Симптом обманчив: выглядит как «UI не обновился», а это упавший запрос.
- **Параметр, обработанный только в одной ветке роутера, «работает» и не работает одновременно.**
  `?screen=1` (ужатые обои) я обработал в loopback-ветке — киоск получал 68 КБ, а браузер из
  локалки шёл в авторизованную ветку и получал оригинал 1.6 МБ. Проверять надо ТЕМ ЖЕ путём,
  каким ходит пользователь: `curl` с `127.0.0.1` доказывал «всё хорошо», пока пользователь видел
  обратное.
- **Скриншот с `grim -c` рисует курсор сам.** Флаг просит композитор дорисовать указатель — по
  такому кадру нельзя судить, виден ли курсор на панели. Для проверки вёрстки — `grim` без `-c`.
- **Прогресс — НЕ заполнение: порогами его красить нельзя.** `bar(pct)` на экране по умолчанию
  красит полосу как заливку диска (≥75 % жёлтый, ≥90 % красный). Той же функцией рисовали ход
  бэкапа и USB-импорта → успешный прогон под конец становился КРАСНЫМ, и это читалось как авария.
  Прогресс-полоса — свой класс (`.bar>i.pg`, акцент). Правило шире одной функции: у «сколько
  осталось» и «сколько занято» ПРОТИВОПОЛОЖНЫЙ знак — 95 % копии это хорошо, 95 % диска плохо.
- **История на настенном экране обязана пережить ребут.** Плашки USB-импорта/бэкапов должны
  отвечать «когда это было в последний раз» и с холодного старта, а прогресс-файлы импорта живут
  в `/run` (умирают с боксом) и вычищаются через 600 с после финиша. Постоянный след — тот, что
  `usb_ops_sync()` пишет в `ops-history.json`; экран читает его (`usb_import_history()`), а не
  `/run`. Слова «готово» на плашке нет намеренно: зелёная точка + ДАТА («вчера 21:40») отвечают
  и «всё хорошо», и «когда» — а «готово» без даты не отвечает ни на что.
- **JS на боксе без node проверять нечем.** Дважды ловил синтаксическую ошибку только по пустой
  странице (скрипт не выполняется — значит и `catch` не сработает, и ошибки не увидишь). На боксе
  с экраном ставь `nodejs` и гоняй `node --check` на вынутом `<script>` — это дешевле, чем
  отлаживать белый экран.
- **Флаги Chromium НЕ убирают всплывашки — только managed policy** (`/etc/chromium/policies/managed/*.json`, кладёт
  `install_screen()`; профиль при этом снести — показ плашки запоминается в нём). `cage` берёт VT: юниту нужны
  `Conflicts=getty@tty1` + `PAMName=login`, иначе нет seat0/DRM master.
  Полная история: `docs/incidents.md`.
- **Обои под стеклом: `z-index:-1` уезжает ЗА фон `body`.** Фон-слой с отрицательным z-index
  рисуется ниже фона body, и непрозрачный `body{background:#0a0f18}` его просто закрашивал —

- **Бокс без дисков = красный smartmontools** (DEVICESCAN пуст → exit 17 → failed; ложная тревога). Лечит
  `install_smartd_guard()`: `ConditionPathExistsGlob` sd*/nvme* (нет дисков → inactive, не failed); `Type=simple`+

  udev поднимает smartd при первом диске — только start, слепой restart будил бы спящие диски.

- **`Type=oneshot` без `RemainAfterExit` + `WantedBy=sysinit.target` = «failed» из пяти УСПЕШНЫХ прогонов**:

  `RemainAfterExit=yes` (пишет `install_fake_hwclock`). `failed` при коде 0 — почти всегда рейт-лимит стартов.
  Полная история: `docs/incidents.md`.
- **Pi без RTC: после ребута часы СТУХШИЕ, и писатель журналов по epoch их отравляет** (netguard до NTP-синка стёр

  можно, только убедившись, что «сейчас» ≥ метки.
  Полная история: `docs/incidents.md`.
- **Правка `nas-wizard.sh` НЕ обновляет установленные им скрипты.** Вчерашний фикс avail-журнала

  портиться «починенным» кодом. После правки генератора — сразу `nas-wizard.sh api <секция>`
  (для сторожа: `api netguard`) на КАЖДОМ боксе, где это уже стоит.

## Уведомления: состояние ≠ событие (2026-07-27)
Полный разбор, все грабли и миграция — `docs/notifications.md`. Правила, действующие всегда:
- **Состояние — не событие.** `_EVENT_COND` (обновления, температура, «бэкап не ходил»…) — ОДНА живая запись: счётчик `n`, апгрейд уровня, не размножается даже после прочтения. Настоящие события пишутся каждый раз.
- **Телефон — только для неотложного.** `_PUSH_NOW` — короткий список; `push_mode` = important (умолчание) | all | off. Канал, звонящий по любому поводу, выключают целиком — и теряют важное.
- **Остальное — вечерняя сводка** `_events_digest()` из САМОГО журнала; пустой день отвечает «Nothing needs you».
- Заглушенный режимом тумблер обязан это показывать (подпись «rings» / `.is-gated`) — включённый, но неработающий переключатель врёт.
- Ленту сортировать по `t2||t` (у состояния время двигается); чистку журнала вести по ПОСЛЕДНЕЙ активности и звать В НАЧАЛЕ `log_event`; «System started» писать только при аптайме <5 мин.

## Рабочий стол: скрытие иконок и пути возврата (2026-07-27…30)
Полные разборы (три поломки пути возврата, меню, длинные нажатия, рамка выделения) — `docs/desktop.md`. Правила:
- Контекстное меню на вложенном элементе БЕЗ `e.stopPropagation()` не работает — родитель тут же затирает его своим; у родителя — хит-тест «моё ли событие». Проверять КЛИКОМ, не чтением кода.
- На таче нет ПКМ: действие, живущее только в контекстном меню, там НЕ СУЩЕСТВУЕТ — длинное нажатие (`longPress`, 500 мс) или дубль в настройках.
- Путь ВОЗВРАТА проверять кликом отдельно от пути скрытия — их ломают по отдельности; обратная операция обязана быть видимой на той же поверхности, где сделали прямую (`deskRestoreItems()`, бейдж `.lp-off` в Launchpad).
- Рендер-функцию вызывать из строителя ТОЙ вкладки, где лежит её контейнер; ранний `if(!box)return` — молчаливая поломка, ищи его первым; настройка, которую читает только рендерер, обязана дёргать этот рендерер из обработчика.
- Если действие охватывает не всё, что обещает имя, разницу называет сам пункт («Show shortcuts (N stay hidden)»).
- То, что появляется САМО (docker-ярлыки), обязано иметь видимое место управления (`lsAppsList` в Настройках), а не только контекстное меню.

## Правила, добытые практикой
Каждое — цена уже совершённой ошибки. Подробности в `docs/`.

- для скриптовых правок desktop.html: якорить поиск от УНИКАЛЬНОГО комментария секции приложения, резать до СЛЕДУЮЩЕГО известного определения и ASSERT'ить, что в вырезаемом куске ровно ожидаемое число `function` и нет чужих маркеров (winResil/winRclone…).
- пикер папок в панели ОДИН — `pickFolder`; не плодить свои.
- дизайна детали: важное и крупное сверху (что бэкапим), метрики плитками, история — с легендой и понятной единицей; настройки — свёрнуты.
- любое поле в диалоге, у которого Enter имеет СВОЙ смысл (поиск, навигация, создание), обязано нести `data-noenter` — иначе оно молча делает ДВА действия.
- недоступный вариант лучше показать выключенным с причиной, чем спрятать.
- любой новый `toLocale*` — только с `LOC`.
- баланс иконок — ОПТИЧЕСКИЙ (насколько глиф заполняет свой бокс), не по CSS-размеру; RAW_LOGOS обычно надо подкручивать scale/translate под квадратный бокс.
- тесты, вызывающие мутирующие kp-функции, обязаны восстанавливать состояние (пароль, backups, history ts).
- в СВЕТЛОЙ теме различать поверхности внутри окна заливкой нельзя (всё белое) — только тонировка/рамка/тень.
- не используй «поле = null» как способ инвалидировать кэш, если это же значение служит чужому коду сигналом «инициализируйся» — race неизбежен.
- наличие/отсутствие пинов проверять серверно по ВСЕМУ репозиторию (`kp_snapshots` → `pins`), а не по UI одной папки.
- в шкале, по которой ходят, ни ширина, ни вес шрифта не должны зависеть от выбора.
- вердикт проверки не имеет права быть оптимистичнее собственных наблюдений.
- если пользователь боится нажать кнопку — объяснение должно жить В приложении, а не в голове и не в git.
- аккордеоны хороши для одного скрытого блока; когда их становится два и больше — это уже вкладки.
- «предыдущее значение» для сравнения бери из последнего УСПЕХА, а не из последней записи.
- разные файлы под одним URL нельзя валидировать датой — им кэш противопоказан.
- перед подкруткой масштаба логотипа смотри его `getBBox()` — если арт уже упирается в границы viewBox, любой масштаб >1 это обрезка, а не увеличение.
- меняя набор значений у модульной переменной-состояния, добавляй нормализацию — старое значение переживает перезагрузку страницы (и живёт в чужих вкладках).
- на боксе без RTC проверять не `who -b`/`--list-boots`, а `/proc/uptime` — они расходятся ровно на величину скачка.
- если инструмент умеет делать тяжёлую работу «когда придётся», а мы делаем её по расписанию — автоматику надо гасить, иначе она однажды случится внутри чужой короткой операции.
- подготовительный шаг не имеет права стоить главного, если его результат уже есть в системе.
- если у режима есть сторож, исполняющий его автоматически, то ручное действие, обратное режиму, обязано либо снять режим, либо быть отклонено с объяснением — молча проигрывать сторожу кнопка не имеет права.
- у периодической задачи порог тревоги обязан быть соизмерим с её ПЕРИОДОМ, а не выбран «на глаз»; для ежедневной задачи неделя тишины — это не порог, это отсутствие контроля.
- для любого расписания в этом проекте: слот — это ИНТЕРВАЛ «должен был к моменту X», а не минута-совпадение; и он обязан лежать на диске.
- то, что читается на уровне модуля, не имеет права бросать — иначе бокс теряет веб-интерфейс из-за одной строки в файле состояния.
- прежде чем оптимизировать РАЗМЕР ИСХОДНИКА, посмотри, что реально уходит в сеть — заголовок ответа отвечает на этот вопрос за секунду.
- вопрос «можно ли это сохранить» задаётся при ОТКРЫТИИ, а не после того, как человек напечатал текст; отказ, о котором сообщает исчезающий тост, эквивалентен молчанию.
- любой кэш/валидатор, ключуемый по времени файла, обязан быть наносекундным — секунда это вечность для генератора правок.
- скрипт `web/desktop.html` целиком обёрнут в `(function(){"use strict"; … })()` — на `window` НЕТ ничего. Проверять UI через CDP можно только КЛИКАМИ по DOM (что и правильнее — так делает человек); `Runtime.evaluate` с именем функции панели вернёт `undefined`, и это не поломка.
- у теста, подменяющего файловую систему, надо закрыть ВСЕ двери в неё (`os.listdir` + `os.path.exists` + `_read`): забытая третья дала тесту прочитать настоящий `/sys` и «пройти» по неправильной причине.
- «есть устройство» ≠ «оно работает»: наличие узла в `/dev` ничего не говорит о том, что за ним живое железо — проверяй способность, а не присутствие файла.

Идеи в бэклоге: «топ самых больших файлов» в анализаторе; пользовательские glance-проверки из
`/var/lib/nas-os/scripts`; ИБП/NUT (graceful shutdown при отключении питания — главный оставшийся
сценарий потери данных). Вычеркнуто осознанно (2026-08-05):
Telegram-бот (второй канал туда же, куда Pushover со сводкой = снова шум), спарклайны в плитках
(косметика без запроса). Бэкап наружу — сторонним сервисом в Docker (zerobyte).
